What this means

The picture in three parts

Working well

The daily nursery runs on XO

  • Admissions, sign-up, enrollment and child records
  • QR attendance, safe pickup and late-pickup billing
  • Events with digital permission slips
  • Invoices, manual payments, reminders and finance reports
  • Staff records, payroll and payslips
  • Chat, broadcasts and in-app notifications
  • Photos with approval, daily and quarterly reports
  • Arabic and English, every role on its own home page
Fix first

Problems found on 12 Oct

  • Account security: new staff share one password and the account list is public
  • Teachers cannot load their children (fix written)
  • 12 database updates are not in production yet
  • XO admin and managers cannot see applications or courses
  • Teachers can see nursery money totals
  • Data export service not deployed

All of these are in phase 1, which ends Thu 22 Oct 2026.

Not built yet

Gaps that limit growth

  • Email, SMS and WhatsApp delivery
  • Push notifications to phones
  • Automatic online payment confirmation
  • Forgot-password flow
  • Automated tests and error monitoring
  • Ledger, refunds and payroll approval
  • CCTV, bus tracking and the other interview features
Recommendation

Do phase 1 before onboarding another nursery. Phases 1 to 5 make the platform complete and safe to scale (done around Mon 25 Jan 2027). Phase 6 adds new features and can move as priorities change.

How the statuses were decided

Each status comes from a review of the code and a live check on 12 Oct 2026: 401 pages were opened as seven kinds of user (public visitor, XO admin, branch admin, finance manager, HR manager, teacher and parent), read-only, with a screenshot of every page. Saving actions (forms, payments, attendance) were not exercised on production; testing them on a private copy is task T2.1.

StatusMeaning

Needs fixBuilt, but broken, unsafe or waiting for a production update.
Not startedPlanned, no code yet, or the code only prepares for it.

Read before relying on dates

Assumptions

Capacity and calendar

  • One developer, 5 hours a day, Sunday to Thursday: 25 hours a week.
  • Starts Tue 13 Oct 2026. Tasks run one after another, in the order shown.
  • Public holidays, leave and sick days are not included; add one day per day off.
  • Each phase ends with a testing and fixes buffer (about 12%).

Estimates

  • Hours assume the developer works with AI coding tools, as today.
  • Treat estimates as ±30%: larger items (ledger, bus tracking, CCTV) carry the most uncertainty.
  • Outside providers (Paymob, SMS, WhatsApp, cameras) need accounts and approvals that can add waiting time.
  • Phase 6 can be reordered or dropped without affecting phases 1–5.

What the statuses are based on

  • Code review of the whole project on 11 Oct 2026.
  • Live read-only check of 401 pages as seven kinds of user on 12 Oct 2026.
  • Production database compared with the code (12 updates waiting).

Keeping this document current

  • Statuses, tasks and hours live in docs/pdf-source/build-feature-status.cjs.
  • Change a status or an estimate, run the script, then build-pdfs.ps1 status: dates and charts update themselves.
